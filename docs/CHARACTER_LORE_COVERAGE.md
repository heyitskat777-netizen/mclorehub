## What the inventory includes

Core practices, feats, referenced marriage/ritual extensions and creature sources
are available. Extensions do not become separate parent magic applications. Some
feats use an MA in their source (e.g. Atronach Forging); the label keeps that explicit.
Core racial/cultural records remain wiki references, not automatic CA choices.
Hubs, inventions/materials, source amendments and artifacts are not extra independent
magics. Shared creature forms retain a reference label rather than an invented
single eligibility rule. No source match does not prove nonexistence or denial.

## Conditions and unresolved text

Seer/Templar, Seer/Cleric, Druid/Templar and Nephilim/bonded-Seer contradictions remain
explicit source disagreements. Prior Ordained Herald → Nephilim, Silit/Seer acquisition
order, Sprite/Herblore, Druid/Seer Greensight and mutation-specific Kani effects are
conditional cases. Exact source text stays accessible. Core rules are inherited only
through explicitly curated dependencies, not runtime title/category heuristics.

Slot policies include standard feat treatment, explicit numeric costs/ranges and
documented optional/permanent cases. Some source texts do not state an amount;
those retain unknowns until a user records an explicit allocation. Numeric records
do not verify training, age, consent, prerequisite completion or server approval.

Changed source revisions suspend dependent rules. All other personal data remains
available. See [release workflow](RELEASE_1_0.md), [installation](INSTALL.md), and the
[original curation procedure](PHASE_8.md#future-curation-procedure). Add matching
source evidence, preserve exceptions and run behavior/stale-source checks before
curating a new rule. Unknown is not compatible.
